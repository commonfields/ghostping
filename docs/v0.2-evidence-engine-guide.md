# Ghostping v0.2 Evidence Engine - User Guide

## Overview

Ghostping v0.2 introduces an evidence-first approach to Generative Engine Optimization (GEO). This new workflow provides:

- **Project-level configuration** via `ghostping.toml`
- **Multi-sample audits** for statistical significance
- **Prompt discovery** with intent categorization
- **Raw evidence storage** for transparency
- **Content generation** from audit gaps
- **Before/after comparison** of audit runs

## Quick Start (Evidence Engine)

```bash
# 1. Initialize a new project
ghostping init

# 2. Discover prompts based on your project config
ghostping prompts discover

# 3. Run a mock audit (no API keys needed)
ghostping audit run --models mock --samples 3

# 4. View audit results
ghostping audit list
ghostping audit show 1

# 5. Generate a markdown report
ghostping report --output ./reports/

# 6. Generate content assets from gaps
ghostping generate --output ./generated/

# 7. Compare two audit runs
ghostping audit compare --before 1 --after 2
```

## Commands Reference

### `ghostping init` - Initialize Project

Creates a `ghostping.toml` file in the current directory.

```bash
# Interactive mode
ghostping init

# Non-interactive with defaults
ghostping init --yes

# Specify project details
ghostping init --name "MyProject" --website "https://example.com" --category "developer tool"

# Overwrite existing config
ghostping init --force
```

**Generated `ghostping.toml`:**
```toml
[project]
name = "MyProject"
website = "https://example.com"
category = "developer tool"
description = ""
audience = []

[competitors]
names = []

[keywords]
topics = []

[providers]
default = "ollama"
models = ["ollama:llama3.2"]

[audit]
samples_per_prompt = 3
temperature = 0.2
store_raw_responses = true
```

### `ghostping prompts` - Prompt Management

#### `prompts discover`

Generates prompts based on your project configuration.

```bash
# Discover up to 50 prompts (default)
ghostping prompts discover

# Limit to 20 prompts
ghostping prompts discover --limit 20
```

**Prompt Categories:**
- **Category**: "Best tools for X"
- **CompetitorAlternative**: "Alternatives to CompetitorY"
- **ProblemAware**: "How to check if..."
- **SolutionAware**: "What is ProjectX"
- **Comparison**: "Compare X vs Y"
- **BuyerIntent**: "Which should I use"

#### `prompts list`

Shows stored prompts with metadata.

```bash
ghostping prompts list
```

### `ghostping audit` - Evidence-First Audits

#### `audit run`

Runs a multi-sample audit across configured models.

```bash
# Run with default settings
ghostping audit run

# Use mock provider (no API keys needed)
ghostping audit run --models mock --samples 3

# Override specific settings
ghostping audit run --samples 5 --temperature 0.5 --models ollama:llama3.2

# JSON output
ghostping audit run --json
```

**Metrics Collected:**
- Mention rate: % of responses mentioning your project
- Citation rate: % of responses with URLs to your project
- Recommendation rate: % actively recommending your project
- Position: Where in the response you're mentioned
- Sentiment: Positive, neutral, or negative

#### `audit list`

Shows previous audit runs.

```bash
# List last 20 runs
ghostping audit list

# List last 10 runs
ghostping audit list --limit 10
```

#### `audit show`

Shows details of a specific audit run.

```bash
ghostping audit show 42
```

### `ghostping report` - Generate Reports

Creates markdown evidence reports from audit results.

```bash
# Generate report from latest audit
ghostping report

# Generate report from specific run
ghostping report --run 42

# Specify output directory
ghostping report --output ./reports/

# Include full raw responses
ghostping report --full

# Force overwrite existing report
ghostping report --force
```

**Report Sections:**
- Executive Summary
- Detailed Metrics
- Results by Model/Provider
- Prompt-Level Results
- Competitor Analysis
- Citations Found
- Content Gaps & Recommendations
- Raw Evidence Appendix (with --full)
- Methodology & Caveats

### `ghostping generate` - Content Generation

Generates markdown assets based on audit gaps.

```bash
# Generate from latest audit
ghostping generate

# Generate from specific audit run
ghostping generate --from-audit 42

# Specify output directory
ghostping generate --output ./content/

# Force overwrite existing files
ghostping generate --force
```

**Generated Assets:**
- Comparison pages
- Alternatives pages
- Use case pages
- FAQ pages
- Docs summaries
- README patches
- llms.txt

### `ghostping audit compare` - Compare Audit Runs

Shows before/after visibility movement.

```bash
# Compare two runs (terminal output)
ghostping audit compare --before 10 --after 20

# JSON output
ghostping audit compare --before 10 --after 20 --format json
```

**Comparison Metrics:**
- Visibility score delta
- Mention rate delta
- Citation rate delta
- Recommendation rate delta

### `ghostping diagnose` - URL Diagnostics

Checks basic crawlability and AI readiness.

```bash
ghostping diagnose https://example.com
```

**Checks:**
- Homepage reachability
- robots.txt presence
- sitemap.xml presence
- llms.txt presence

## Complete Workflow Example

```bash
# 1. Create a new project directory
mkdir my-geo-project && cd my-geo-project

# 2. Initialize Ghostping
ghostping init --name "MyAwesomeTool" --website "https://myawesometool.dev" --category "CLI tool"

ghostping audit run --models mock --samples 3

# 8. Generate a report

# 9. Generate content from gaps

# 12. Compare the two runs
ghostping audit compare --before 1 --after 2
```

## Configuration

### Project Config (`ghostping.toml`)

```toml
[project]
name = "MyProject"
website = "https://myproject.dev"
category = "AI visibility tool"
description = "A local-first AI visibility workbench for developers"
audience = ["indie hackers", "solo founders", "open-source maintainers"]

[competitors]
names = ["CompetitorA", "CompetitorB"]

[keywords]
topics = ["AI visibility", "GEO", "ChatGPT mentions"]

[providers]
default = "ollama"
models = [
    "ollama:llama3.2",
    "openai:gpt-4o-mini",
    "anthropic:claude-3-haiku"
]

[audit]
samples_per_prompt = 3
temperature = 0.2
store_raw_responses = true
```

### Global Config (`~/.ghostping/config.toml`)

API keys and global settings remain in the global config:

```toml
[providers.openai]
api_key = "sk-..."
model = "gpt-4o-mini"
enabled = true

[providers.ollama]
base_url = "http://localhost:11434"
model = "llama3.2"
enabled = true
```

## Data Storage

All evidence is stored locally in SQLite:

- `~/.ghostping/evidence.db` - Audit runs, results, prompts
- `~/.ghostping/mentions.db` - Legacy data (preserved)

## Privacy

- All project data stays in `ghostping.toml` (local)
- All audit data stays in local SQLite
- Only prompts sent to configured providers
- No telemetry or external data transmission
- API keys never logged or stored in project files

## Mock Provider

For testing without API keys:

```bash
ghostping audit run --models mock --samples 3
```

The mock provider returns predictable responses for testing the workflow. It validates local behavior such as storage, reports, generated files, and comparisons; it does not measure real AI visibility in live models.

## Tips

1. **Start with mock**: Test your workflow with `--models mock` before using real providers
2. **Use samples**: Set `samples_per_prompt = 3` or higher for statistical significance
3. **Iterate**: Run audits, generate content, publish, then re-audit to measure improvement
4. **Compare**: Use `ghostping compare` to track progress over time
5. **Store raw responses**: Keep `store_raw_responses = true` for debugging and evidence

## Troubleshooting

### "No ghostping.toml found"
Run `ghostping init` first to create a project configuration.

### "No providers configured"
Either:
- Use `--models mock` for testing
- Configure providers in `~/.ghostping/config.toml`

### "No prompts found"
Run `ghostping prompts discover` to generate prompts from your project config.

### "No audit runs found"
Run `ghostping audit run` first to create audit data.

## Migration Notes

### From v0.1 (Legacy Commands)

The v0.2 evidence engine is fully backward compatible:
- Existing commands continue to work (now named `audit-legacy`, `report-legacy`, `generate-legacy`)
- Legacy data in `mentions.db` is preserved
- New evidence data goes to `evidence.db`

### From v0.2 Temporary Commands

The temporary `*2` command names have been promoted to clean command names:

| Old Command | New Command |
|-------------|-------------|
| `ghostping init2` | `ghostping init` |
| `ghostping prompts2 discover` | `ghostping prompts discover` |
| `ghostping prompts2 list` | `ghostping prompts list` |
| `ghostping audit2 run` | `ghostping audit run` |
| `ghostping audit2 list` | `ghostping audit list` |
| `ghostping audit2 show` | `ghostping audit show` |
| `ghostping report2` | `ghostping report` |
| `ghostping generate2` | `ghostping generate` |
| `ghostping diagnose2` | `ghostping diagnose` |
| `ghostping compare` | `ghostping audit compare` |

The old `*2` commands will continue to work with a deprecation warning.

## Next Steps

1. **Customize your `ghostping.toml`** — Add competitors, keywords, and audience
2. **Run your first real audit** — Use actual providers (not just mock). Live provider testing requires valid API keys, and cloud providers process the prompts sent to them.
3. **Generate content from audit gaps** — Address where competitors are mentioned
4. **Publish the content** — To your website, docs, or blog
5. **Re-audit to measure improvement** — Use `ghostping audit compare` to track progress
6. **Iterate** — Expect 2-4 audit cycles before seeing meaningful movement
